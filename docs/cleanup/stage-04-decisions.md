# Stage 04 model-construction decisions

| Category | Current assessment | Semantic boundary / validation
|---|---|---|
| Mesh and quadrature setup | In inventory. Constructors commonly create GLL quadrature and a transform grid, but mesh calls differ in physical/referential radii and constructor inputs. | No shared setup extraction until operation order and `RadialMesh` semantics are confirmed identical.
| Storage initialization | Extracted `GPLSpec::model_detail::InitializeScalarFieldStorage` and replaced seven identical nested allocations for mapping/Jacobian arrays, passing their existing zero/one initial values explicitly. | Preserves shape `(elements, quadrature nodes, spatial samples)` and each original initial value. `stage04_construction_storage` compares against the original nested initializer, including empty dimensions and zero/one/negative values. Full build, public-header checks, and examples pass; all three frozen 20,700-record comparisons have zero differences and representative output is byte-identical.
| Density sampling | In inventory. Physical constructors multiply their physical density by the Jacobian; model/tomography constructors sample radial density and may apply tomography without the same factor. | Keep physical versus referential semantics explicit; no shared sampler across these paths without exact equivalence.
| Mapping geometry | Extracted `PopulateRadialMappingGeometry` for the physical-radius and referential mapped constructors, whose loops use the same layer/node/spatial order, radius clamp and exterior taper. The aspherical file constructor builds geometry from transformed radius coefficients and remains separate. | `stage04_mapping_geometry` compares the output field and mapping-call count against the copied original loop, including points inside and outside the planet radius. The frozen mapped-model fixture compares mapping, Jacobian, inverse-F and Laplace-tensor arrays. Distinct transformed-radius geometry remains separate.

Each extraction is a separate logical commit. Original-source stage-00 references remain fixed; expected outputs are never regenerated from the candidate.
