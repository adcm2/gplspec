# Stage-02 header organization decisions

- Supported umbrella headers remain at their existing paths: `gplspec/Core`, `gplspec/SimpleModels`, `gplspec/GeneralModels`, and `gplspec/All`. Standalone smoke translation units verify each umbrella directly. `Core` provides shared radial/operator/preconditioner utilities; `SimpleModels` defines base models; `GeneralModels` composes model and gravity APIs; `All` composes both model umbrellas and core tools.
- Headers under `gplspec/src` remain implementation fragments included through the existing umbrella/API. The matrix wrapper fragments now include the specific model declarations their constructors and members name; umbrella compile no longer depends on a prior unrelated include. Existing file paths and public class names are unchanged.
- The `gplspec` CMake interface now propagates Eigen, GaussQuad, GSHTrans, FFTWpp, PlanetaryModel, and TomographyModels dependencies directly required by its public header closure.
- The two-TU `<gplspec/All>` executable initially exposed GPLSpec multiple definitions in non-template model, radial/spectral, gravity, mapping, and utility functions. Added `inline` declarations/specifiers only; function bodies and ownership remain unchanged.
- The same consumer exposed seven header-defined external non-template functions in the pinned FFTWpp (`06cc1fb04c4398407839e637cb5414b179b0e9c3`) and TomographyModels (`97869aeea3f3d87901705db59b5de975960bd9e1`) dependencies. `cmake/patches/stage02-fftwpp-odr.patch` and `stage02-tomographymodels-odr.patch` add only `inline` to those seven definitions. CMake applies these repository-local patches idempotently to per-build FetchContent source copies after verifying all seven markers. Dependency revisions and shared/local cached checkouts are unchanged.
- Baseline regression confirms these linkage/include changes do not alter captured numerical records or output. No stage-03 utility extraction was started.
